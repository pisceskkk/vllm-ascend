vLLM Ascend Attention 后端算子与输入格式分析报告

范围：当前 vllm_ascend/attention/ 中的 attention_v1.py、mla_v1.py、sfa_v1.py、 dsa_v1.py。报告重点回答每个 backend 实际使用哪些 attention 相关算子、 q 与 KV/KV cache 的输入布局是什么、以及这些路径相对其他 attention 后端的功能差异来源。

总体结论

attention_v1.py 通用 MHA/MQA/GQA 后端。主算子是 npu_fused_infer_attention_score、 npu_fused_infer_attention_score_v2 和 _npu_paged_attention， KV cache 是传统 K/V 双 cache。
mla_v1.py MLA latent-cache 后端。KV cache 不再保存完整 K/V，而保存 latent KV 与 RoPE K； decode 用 FIA v2 的 query_rope/key_rope 输入，输出 latent 后再做 V up-proj。
sfa_v1.py Sparse Flash Attention 后端。沿用 MLA latent 表示，但额外维护 indexer cache， 用 lightning indexer 产出 top-k，再调用 sparse flash attention 只访问稀疏 KV。
dsa_v1.py DSV4/DSA sparse shared-KV 后端。将 sliding-window 原始 KV 与压缩历史 KV 组合起来， 通过 shared-KV sparse attention 算子完成 SWA + compressed KV 混合注意力。
核心差异： attention_v1 是“完整 K/V + block table”的通用路径； mla_v1 是“latent KV + RoPE split”的 MLA 路径； sfa_v1 是“MLA latent KV + top-k sparse index”的稀疏路径； dsa_v1 是“原始 SWA KV + 压缩 KV + sharedkv sparse metadata”的 DSV4 路径。 因此它们的 cache 内容、attention operator、metadata、量化与 RoPE 位置都不完全一致。

布局术语

布局/对象 含义 典型出现位置
TND T 是 batch 内打包后的 token 总数，N 是 head 数，D 是 head dim。 FIA prefill、普通 attention、MLA/SFA/DSA 的 query 侧。
PA / paged cache 通过 block_table 从 request 映射到物理 block；cache 一般是 [num_blocks, block_size, N, D] 或同语义变体。 decode、chunked prefill、prefix cache hit。
PA_BSND / PA_ND 稀疏算子使用的 paged KV cache 布局标记。PA_BSND 常用于 lightning indexer 与 sparse flash；PA_ND 常用于 DSA shared-KV。 sfa_v1.py、dsa_v1.py。
BNSD / BSND_NBSD / BNSD_NBSD / TND_NTD decode 或图模式下为了满足 CANN/FIA v2 输入输出 layout 约束使用的变体，右侧后缀表示输出布局。 MLA decode、C8/FA quant、spec decode。
actual_seq_lengths* FIA/SFA/DSA 算子需要的累计 query 长度、KV 长度或每请求长度；决定 mask、causal、block table 的有效范围。 四个 backend 都使用，但字段名和是否为 list/tensor 不同。

算子总览

算子/包装 使用后端 主要用途 输入格式要点
torch_npu.npu_fused_infer_attention_score attention_v1, mla_v1 FIA v1，普通 prefill/chunked prefill/非 sink attention；MLA prefill 和 chunked context 合并前的局部 attention。 普通路径用 query/key/value TND；MLA prefill 用 q_nope + query_rope 或拼接后的 full query。
torch_npu.npu_fused_infer_attention_score_v2 attention_v1, mla_v1 支持 learnable sink、MLA decode 的 RoPE split、图捕获 replay。 普通路径可用 TND；MLA decode 传 q_nope、k_nope、value=k_nope，并额外传 query_rope/key_rope。
torch_npu._npu_paged_attention attention_v1 DecodeOnly 下的传统 paged attention 快路径。 query=[T,H,D]，key_cache/value_cache=[num_blocks,block_size,Hkv,D]，配合 block_table/context_lens。
torch_npu.npu_fusion_attention attention_v1 pooling / encoder-only 非 causal attention。 TND query/key/value，使用相同 actual_seq_qlen/kvlen。
torch_npu.npu_kv_rmsnorm_rope_cache mla_v1, sfa_v1 MLA/SFA KV 预处理：对 latent KV 做 RMSNorm、拆出/旋转 RoPE K，并写入 paged cache。 输入 kv_no_split reshape 为 [B,N,1,kv_lora_rank+qk_rope_head_dim]，slots 为 paged cache index。
torch.ops._C_ascend.mla_preprocess / torch_npu.npu_mla_prolog_v2/v3 mla_v1, sfa_v1 MLAPO/prolog：融合 q/kv down-proj、RMSNorm、RoPE、cache 写入和 q_nope 变换。 输入 hidden states，输出 q_nope/ql_nope、q_pe、可选 q_c，并直接写 latent KV cache。
torch_npu.npu_sparse_flash_attention / torch.ops._C_ascend.npu_sparse_flash_attention sfa_v1 SFA 主 attention：按 indexer top-k 稀疏读取 KV。 query=ql_nope，key=value=latent KV cache，query_rope=q_pe，key_rope=k_pe cache，layout 为 TND + PA_BSND。
torch_npu.npu_kv_quant_sparse_flash_attention sfa_v1 A5/C8 量化 SFA 主 attention。 将 ql_nope 与 q_pe 拼成 query；KV 是量化 cache，不再单独传 key_rope。
torch_npu.npu_lightning_indexer / torch.ops._C_ascend.npu_lightning_indexer* sfa_v1, dsa_v1 根据 query/indexer key 选出 sparse top-k KV block 或 token index。 query 多为 TND，key 是 paged indexer cache，layout 常为 PA_BSND。
torch.ops._C_ascend.npu_sparse_attn_sharedkv* dsa_v1 DSA 主 attention：同时处理 sliding-window 原始 KV 与 compressed KV。 q 是 TND；ori_kv 是 SWA cache；cmp_kv 是压缩 cache；layout 为 TND + PA_ND。
torch.ops._C_ascend.compressor dsa_v1 生成 compressed KV，并维护 compressor state cache。 输入 hidden states、compressor 权重、state cache、RoPE sin/cos、block table、start position。
_npu_reshape_and_cache / npu_scatter_pa_kv_cache / scatter/update wrappers 全部相关路径 将当前 token 的 KV 写入 paged cache。 普通 K/V、MLA latent KV、SFA indexer KV、DSA SWA/compressed KV 的写入方式不同。

attention_v1.py：通用 MHA/MQA/GQA

输入与 cache 形态

  • query: [num_tokens, num_heads, head_size]。
  • key/value: [num_tokens, num_kv_heads, head_size]。
  • kv_cache: backend 声明为 [2, num_blocks, block_size, num_kv_heads, head_size]，运行时拆成 key_cache=kv_cache[0] 与 value_cache=kv_cache[1]。
  • PrefillNoCache 直接使用本轮 TND K/V；PrefillCacheHit、DecodeOnly、ChunkedPrefill 使用 paged cache 与 block_tables。

attention 算子路径

场景 算子 布局/参数 用途差异
DecodeOnly + paged attention 快路径 torch_npu._npu_paged_attention query + key_cache/value_cache + block_table/context_lens。 只处理 decode，避免 FIA 对短 query 的额外开销。
普通 causal prefill / chunked prefill / cache hit npu_fused_infer_attention_score input_layout="TND"，sparse_mode=3，可传 atten_mask 与 paged block_table。 标准全量 causal attention，适配完整 K/V。
Sliding window npu_fused_infer_attention_score sparse_mode=4，pre_tokens=sliding_window，next_tokens=0。 窗口 mask 由 FIA 参数表达，不改变 K/V 格式。
Learnable sink npu_fused_infer_attention_score_v2 actual_seq_qlen/actual_seq_kvlen，learnable_sink，TND。 FIA v1 不覆盖 sink 语义，因此切到 v2。
Pooling / encoder-only 非 causal npu_fusion_attention TND，sparse_mode=0 语义。 无需 causal mask 与 paged decode 逻辑。
C8/QuaRot INT8 KV cache npu_fused_infer_attention_score + antiquant 参数 decode 可用 input_layout="BNSD"；KV cache 以 NZ 5D view 传入，附带 key/value_antiquant_scale。 cache 是 INT8/NZ，必须在 attention 内反量化。

mla_v1.py：MLA latent cache

输入与 cache 形态

  • 入口输入是 hidden_states，不是直接传入完整 q/k/v。backend 内部先做 fused_qkv_a_proj 或 kv_a_proj_with_mqa。
  • q_c: query latent，经过 q_a_layernorm 后用 q_proj 得到 q_nope 与 q_pe。
  • kv_no_split: [T, kv_lora_rank + qk_rope_head_dim]，进入 npu_kv_rmsnorm_rope_cache 前 reshape 为 [B, num_kv_heads, 1, kv_lora_rank + qk_rope_head_dim]。
  • kv_cache[0] 保存 latent KV / k_nope 基础，kv_cache[1] 保存 RoPE 部分 k_pe。它不是普通 attention 的完整 K/V 双 cache。

attention 算子路径

阶段 算子 q / KV 输入 用途差异
KV 预处理与写 cache npu_kv_rmsnorm_rope_cache kv_no_split=[B,N,1,L+R]，slots 写入 kv_cache[0/1]；返回 k_pe 与 k_nope/kv_c_normed。 把 MLA 的 latent KV 与 RoPE K 在 cache 中拆开保存，降低 KV cache 成本。
Decode attention npu_fused_infer_attention_score_v2 query=q_nope，key=k_nope，value=k_nope，额外传 query_rope=q_pe、key_rope=k_pe。 attention 输出仍在 latent value 空间，之后通过 W_UV 做 V up-proj。
Prefill attention npu_fused_infer_attention_score 若 head 数无需 padding：query=q_nope、key=k_nope、value=v，用 query_rope/key_rope 表达 RoPE；否则拼接 nope/rope。 prefill 有本轮完整 token，可直接由 kv_b_proj 还原 k_nope/value。
Chunked context npu_paged_cache_load + npu_fused_infer_attention_score + npu_attention_update 从 paged latent cache 加载历史 chunk，逐 chunk 做 attention，最后用 LSE 与 output 合并。 解决长上下文 chunked prefill 中当前 chunk 与历史 context 的合并。
Decode-only MLAPO/FA quant 快路径 mla_preprocess 或 npu_mla_prolog_v2 输入 hidden_states，融合生成 q_nope/q_pe 并写 k_nope/k_pe cache。 减少 projection、RMSNorm、RoPE、cache write 的分散开销；受 token 数和量化条件限制。

sfa_v1.py：Sparse Flash Attention

输入与 cache 形态

  • SFA 继承 MLA 的 latent 表示，主 query 是 ql_nope 与 q_pe，而不是普通 full q。
  • 非 C8 常见 cache：kv_cache[0] 为 latent KV / k_nope，kv_cache[1] 为 k_pe，kv_cache[2] 为 indexer K cache，量化 indexer 时还有 scale cache。
  • A5/C8 sparse indexer 下，cache tuple 形态变化：主 sparse attention 可能直接使用量化 latent KV，indexer key/scale 也可能占用不同 cache 槽位。
  • topk_indices 是 SFA 的关键输入，来自 lightning indexer 或 index cache。

attention 算子路径

阶段 算子 q / KV 输入 用途差异
MLA/SFA prolog npu_kv_rmsnorm_rope_cache 或 mla_preprocess/npu_mla_prolog_v3 从 hidden states 产生 ql_nope、q_pe、q_c，并写 latent KV cache。 与 MLA 相同的 latent/RoPE split，但会保留 q_c 供 indexer 使用。
Indexer K 生成与写入 npu_rotary_mul / npu_dynamic_quant / scatter 或 store_kv_block k_li 是 indexer key，可能有 k_li_scale。写入 paged indexer cache。 SFA 需要额外的检索空间，用于后续 sparse top-k 选择。
Top-k 选择 npu_lightning_indexer / npu_quant_lightning_indexer / npu_lightning_indexer_quant query=q_li，key=indexer cache，layout TND + PA_BSND，附带 block_table 与 seq lengths。 把全量历史 KV 访问降为 top-k 稀疏访问；可被 index cache 跳过。
Sparse attention npu_sparse_flash_attention query=ql_nope，key=value=kv_cache[0]，query_rope=q_pe，key_rope=kv_cache[1]，sparse_indices=topk_indices。 只对 top-k KV 计算 attention，输出 latent value，再做 _v_up_proj。
C8/FP8 sparse attention npu_kv_quant_sparse_flash_attention query=cat(ql_nope, q_pe)，key=value=quantized latent KV cache，layout TND + PA_BSND。 量化 KV attention 内部处理 RoPE/反量化模式，调用参数与非 C8 分支不同。

dsa_v1.py：DSA sparse shared-KV

输入与 cache 形态

  • 入口也是 hidden_states，内部生成 q 与 kv。q 经 RMSNorm 与 partial RoPE 后形态为 [T, n_local_heads, head_dim]。
  • SWA 原始 KV：kv=[T,1,nope_head_dim+rope_head_dim]，写入 swa_kv_cache。
  • 当 compress_ratio > 1 时，compressor 生成 compressed KV，写入 compress_kv_cache；同时维护 compressor state cache。
  • 当 compress_ratio == 4 时，额外使用 lightning indexer，维护 indexer K/scale/full cache 并产生 compress_topk_idxs。

attention 算子路径

阶段 算子 q / KV 输入 用途差异
DSA sparse metadata npu_sparse_attn_sharedkv_metadata 或 npu_kv_quant_sparse_attn_sharedkv_metadata 输入 cu_seqlens_q、cu_seqlens_ori_kv、可选 cu_seqlens_cmp_kv、窗口参数、cmp ratio。 DSA 主算子需要专用 metadata 表达 SWA window、compressed KV 和 shared-KV 关系。
SWA KV 写入 dsa_kv_compress_scatter 非 A5 走 npu_scatter_nd_update_v2；A5 走 kv_compress_epilog。 DSA 的 KV 写入不等同普通 K/V cache 写入，A5 还融合量化/压缩。
Compressed KV 生成 torch.ops._C_ascend.compressor 输入 hidden states、compressor 权重、state cache、RoPE sin/cos、block table、cmp_ratio。 把长历史压缩成 cmp KV，用于超出 SWA window 的检索。
Compressed top-k npu_vllm_quant_lightning_indexer query=q_quant，key=indexer_k_cache，带 query/key dequant scale，layout TND + PA_BSND。 ratio=4 时为 compressed KV 选择稀疏候选；ratio=128 分支不传 top-k indices。
DSA 主 attention npu_sparse_attn_sharedkv 或 npu_kv_quant_sparse_attn_sharedkv q TND；ori_kv=swa_kv_cache；可选 cmp_kv=compress_kv_cache；ori/cmp_block_table；layout TND + PA_ND。 同一个 attention 调用融合 sliding-window 近邻 KV 与 compressed historical KV，这是它区别于 SFA/MLA 的核心。

后端差异矩阵

维度 attention_v1 mla_v1 sfa_v1 dsa_v1
适配模型/语义 标准 self/cross/encoder attention，MHA/MQA/GQA。 DeepSeek 类 MLA，latent KV cache。 带 indexer 的 Sparse Flash Attention，MLA latent + top-k。 DSV4/DSA，SWA + compressed KV shared attention。
q 输入 直接 [T,H,D] query。 q_nope + q_pe，或 padding 后拼接。 ql_nope + q_pe；另有 indexer query q_li。 完整 q=[T,H,D]，partial RoPE 已原地应用。
KV cache 内容 完整 K cache + V cache。 latent KV / k_nope + k_pe。 latent KV + k_pe + indexer K/scale cache。 SWA KV + compressed KV + state cache + indexer cache。
主 attention 算子 FIA v1/v2 或 paged attention。 FIA v2 decode，FIA v1 prefill。 Sparse flash attention 或 KV-quant sparse flash attention。 Sparse shared-KV attention 或 KV-quant sparse shared-KV attention。
稀疏性来源 无；sliding-window 只由 mask/window 参数表达。 无；仍是完整 attention，但 KV 是 latent。 Lightning indexer top-k。 SWA window + compressed KV top-k/cmp ratio。
输出后处理 attention output 直接写 output buffer。 decode/prefill 输出需经过 _v_up_proj 和 o_proj。 sparse attention 输出 latent，先 _v_up_proj 再 o_proj。 shared-KV attention 输出进入 _forward_o_proj。
主要独立原因 完整 K/V schema 是 vLLM 标准 attention 基线。 MLA 的 latent/value-up-proj 改变了 KV cache 与 attention value 语义。 top-k sparse indexer 改变了 KV 访问集合和 cache 组成。 compressed KV 与 shared-KV metadata 改变了 attention 的数学结构。

Review 关注点

  • 新增模型选择 backend 时，先确认模型的 KV cache 语义：完整 K/V、MLA latent、SFA sparse latent、还是 DSA compressed shared-KV。
  • 修改 slot_mapping、block_table、actual_seq_lengths* 时，需要分别验证普通 FIA、MLA decode、SFA top-k、DSA shared-KV metadata。
  • 量化路径不能只看 dtype：C8/FP8 往往同时改变 cache view、attention layout、scale cache 和 operator 参数。
  • MLAPO/prolog 属于性能融合路径，不是纯 attention 算子；它改变的是 attention 前的 q/kv/cache 准备方式。
  • SFA 与 DSA 都叫 sparse，但稀疏机制不同：SFA 是 sparse flash + top-k latent KV，DSA 是 shared-KV attention + SWA/compressed KV。
